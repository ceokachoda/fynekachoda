# Spec: Parents' WhatsApp Report

A weekly PDF auto-generated per student, delivered to up to two parent WhatsApp numbers via Gupshup. Also generatable on-demand by teacher or admin.

---

## 1. Goals

- Parents who don't use the app get a structured weekly summary on WhatsApp.
- One PDF, branded with the institute, easy to read on a phone.
- Coverage: attendance %, exam scores (in-app + offline), upcoming exams, optional teacher comment.
- Automated weekly delivery with a manual override.
- Reliable delivery — fallback to email if WhatsApp fails.

## 2. Non-Goals (MVP)

- Parent login / portal.
- Two-way WhatsApp conversations.
- Daily reports.
- SMS as primary channel.
- Voice / video calls.

## 3. Schedule

- **Auto:** every Sunday 18:00 IST via `parent-report-generate` cron.
- **On-demand:** teacher in mobile app or admin in web panel can trigger for any student.

## 5. Generation (Edge Function)

`parent-report-generate`:

**Inputs (auto):** none — iterates all active students with at least one parent phone.
**Inputs (ad-hoc):** `{ student_id, period_start?, period_end? }`.

**Steps:**

1. Compute period: `period_end = nearest Sunday <= now`, `period_start = period_end - 7 days`.
2. For each student:
   - Skip if no parent phones.
   - Aggregate:
     - Attendance counts in window
     - In-app `exam_attempts.submitted_at` in window with released results
     - `offline_test_scores.test_date` in window
     - Mastery top weak topics
     - Upcoming exams (next 14 days, batch-scoped)
     - Teacher's note (`teacher_notes` table — separate from chat; teacher can write a note pinned to a student per period)
     - Current streak + last week's leaderboard rank
   - Render PDF using `pdf-lib`:
     - Layout in `apps/functions/_shared/pdf/parent-report.ts`.
     - Logo loaded from Storage (`badge-assets/logo.png`).
     - Embedded fonts: Inter Regular + Inter Bold.
     - Page size: A4.
   - Upload to `generated-pdfs/{student_id}/{period_end}.pdf`.
   - Insert `parent_reports` row.
   - Build short-lived signed URL (24 hours).
3. For each parent phone:
   - Queue `whatsapp-send` with template `parent_weekly_report`:
     - Variables: `{student_name}`, `{period_label}`, `{attendance_pct}`, `{pdf_url}`.
     - Pre-approved Gupshup template (see template registry).
4. Return summary `{ students_processed, reports_generated, messages_queued }`.

Concurrency: process students in batches of 25, with `Promise.all` and a max of 4 concurrent PDF renders to avoid OOM.

Idempotency: `(student_id, period_start, period_end)` is unique in `parent_reports`. Re-running for the same period overwrites the PDF and re-queues the WhatsApp (but won't re-send if existing message status is `delivered`/`read`).

## 6. WhatsApp Templates

Pre-approved via Gupshup. Template codes:

| Code | Purpose | Variables |
|---|---|---|
| `parent_weekly_report` | Weekly auto-send | `student_name`, `period_label`, `attendance_pct`, `pdf_url` |
| `parent_attendance_alert` | (later phase) Drop in attendance | `student_name`, `attendance_pct` |
| `parent_exam_result` | (later phase) Exam result published | `student_name`, `exam_title`, `score`, `pdf_url` |
| `student_credentials_initial` | Welcome with login creds | `student_name`, `email`, `password`, `app_link` |

Sample template body for `parent_weekly_report`:

> Namaste, {{1}}'s weekly progress report from FyneStudy is here. Attendance this week: {{3}}. Download PDF: {{4}} (link valid 24h). Questions? Reply to this message or call us.

All templates approved through Gupshup partner portal before launch.

## 7. Delivery Flow

```
parent-report-generate
   ↓ (per phone)
whatsapp-send
   ↓ POST to Gupshup
Gupshup → WhatsApp → Parent's phone
   ↓ delivery callback
gupshup-callback edge fn
   ↓
update whatsapp_messages.status
```

## 8. Fallback

If `whatsapp-send` returns failed OR if 24h pass without `delivered` status:

1. Retry once after 1 hour.
2. After second failure, queue an **email** to parent (if parent email captured — optional field on admission).
3. If no parent email, alert admin via in-app notification (admin panel banner).

Email fallback uses Supabase Email Service or a simple Resend integration (later).

## 9. On-Demand Generation

`(teacher)/batch/[id].tsx` → student row → `[Send Parent Report Now]`
`apps/admin/students/[id]/page.tsx` → `[Generate Report]` button

Both call `parent-report-generate` with the student_id and an optional custom period. Confirmation modal shows preview (PDF rendered + parent numbers + estimated cost).

## 10. Audit & Telemetry

- Every send logged in `whatsapp_messages` table.
- Audit log entry on `parent-report-generate` and `whatsapp-send` calls.
- PostHog events:
  - `parent_report_generated` `{ trigger: 'cron'|'admin'|'teacher' }`
  - `parent_report_delivered`
  - `parent_report_failed`

Admin panel `whatsapp` page exposes:
- Recent sends with status
- Delivery rate per template per week
- Failed sends with reason
- Filter by recipient phone (admin only)

## 11. Security Considerations

- PDF URLs are short-lived signed Storage URLs (24h).
- WhatsApp messages contain only minimal info; the full report is behind the link.
- Templates pre-approved — no free-form messages can be sent through WhatsApp from this app.
- Parent phone is PII; access in admin panel is audited.
- Gupshup API key in Supabase Vault; never on client.
- Webhook signature verified (`X-Gupshup-Signature`) before processing callbacks.
- Rate limit: max 1 weekly report send per student per week (cron-enforced); on-demand limited to 1 per 30 min per student.

## 12. Edge Cases

| Case | Behavior |
|---|---|
| Student has no parent phone | Skipped; admin sees "no parent contact" alert on overview. |
| Parent has two phones | Both numbers receive the same message. |
| Same phone shared by multiple students | Sent separately per student (different content). Acceptable. |
| Student suspended | No report generated. |
| Pdf rendering fails for one student | That student is logged + skipped; cron continues. Admin notified. |
| Gupshup template not yet approved | Send fails with `template_not_approved`; admin notified to escalate. |
| Holiday week with no activity | Report still generated with zero/low values + a friendly note. |

## 13. Data Model Touchpoints

- `parent_reports` — generated PDF index
- `whatsapp_messages` — send log + status
- `teacher_notes` (new) — per-student-per-period notes from teacher
- `students.parent_phone_1`, `parent_phone_2`, `parent_email` (optional)

```sql
create table public.teacher_notes (
  id          uuid primary key default gen_random_uuid(),
  student_id  uuid not null references public.students(user_id),
  teacher_id  uuid not null references public.teachers(user_id),
  period_start date,
  period_end  date,
  body_md     text not null,
  created_at  timestamptz not null default now()
);
```

## 14. Edge Function Map

| Function | Trigger | Action |
|---|---|---|
| `parent-report-generate` | Sun 18:00 IST cron; admin/teacher on-demand | Compose + render + queue |
| `whatsapp-send` | Internal | Send via Gupshup |
| `gupshup-callback` | Webhook | Update message status |
| `whatsapp-retry` | Hourly cron | Retry stuck `queued`/`failed` messages |
